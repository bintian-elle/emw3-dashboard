# Cloud Codex read access

User-authorized direct production update, 2026-10-15. Website changes were initially applied directly to production and are now included in the subsequent Concluded/Social release to preserve service access across deployments. Bluevua project helper scripts and access workflow are maintained on the production host under `/home/ubuntu/work/emw3-anc/bluevua/tools/` and `workflows/dashboard-access.md`.

`proxy.ts` verifies independent HS256 service JWTs using server-only `CODEX_SITE_ACCESS_SECRET`. Required issuer/subject: `bluevua-cloud-codex`; audience: `dashboard-read-only`; scope: `dashboard:read`; lifetime at most 15 minutes. The cloud helper mints ten-minute tokens. Accepts Authorization Bearer or HttpOnly `emw3_codex_read` cookie. Valid service credentials precede the crawler user-agent check, but authorize only report pages, selected GET report/media APIs, and four POST data-query endpoints. They cannot authenticate as a Google user, write, call Ask AI, refresh Insights or read personal history via the website's user-scoped API. Ordinary Google login remains unchanged.

The independent key is generated on the production host and saved privately in the website environment and Bluevua's ignored `.local/credentials/dashboard-read.json`. Do not print/commit the key or browser storage state. `node tools/dashboard_read.cjs /bluevua/testing/social` reads the site; `--browser-state` writes a private short-lived storage state for an isolated authorized browser context. The helper restricts origin and refuses cross-origin redirects.

User additionally authorized reading Bluevua Dashboard personal Ask AI history for analytical methods. `python3 tools/dashboard_history_read.py --list`, `--email <email>` or `--insights` reads the private Dashboard conversation projection using SQLite mode=ro and query_only. This does not resume, modify or delete native threads and does not expose other projects or Slack conversations. Pagination uses `--before <timestamp>` and a maximum of 100 turns. Normal users still see only their own histories.

Revoke access by removing or rotating CODEX_SITE_ACCESS_SECRET and restarting the website; rotate both service key copies together. Rollback backup: `/home/ubuntu/work/bintian/.dashboard-ops-backups/codex-site-access-20261015T134627Z`. Does not modify shared Codex/Slack services, website Google credentials or analytics databases.
