# Content Testing 正式站更新清单

> 实施方案：在独立报告存储中准备数据与代码，先用本地正式站验收；本次不部署，也不触发日报或月报。

**目标：** 用最新渠道分析与 readability prompts 生成可长期查阅的日报、周报和月报，保证报告生成与展示一致。

## 范围与验收

- [ ] 正式站采用当前 staging 已验收的 Content Testing 页面、分析呈现、渠道结构、Campaign 详情跳转、Ask AI、社媒排序及最新 prompt；Prompts 页面与批注页面仅供 staging 使用。
- [ ] 摘要紧凑、可视化表达由 AI 自主决定；使用便于理解的素材名称，摘要不展示生硬链接或机器文件名。保留素材画面、图表及分析依据。
- [ ] 在数据库中新建独立的报告存储，按报告类型、周期、对比周期、渠道和语言长期保存；完整结果与依赖素材可供历史查看，不清除旧业务数据。
- [ ] 周报用最新 prompt 生成上周各渠道及 Overview：Campaign 并行生成，汇总渠道后再生成 Overview；本次仅生成上周，不生成日报、月报。
- [ ] 本地正式站从新存储读取该周报，中英文切换复用已保存结果；上线时复用同一份结果，避免重新运行。
- [ ] 每天 12:30 UTC 核对各渠道数据是否已完成当天更新，通过后生成昨日对比前日的日报；未更新或核对失败时不以过期数据生成，并记录可见状态。
- [ ] 每周二 12:30 UTC 生成上周二至周一的周报及相邻前期对比；每月 1 日 12:30 UTC 生成上个完整自然月的月报及上一个完整自然月对比。按约定报告时区判定日期；取消 WTD / MTD。
- [ ] 单日周期和历史报告入口均可查看日报；历史中缺少所选报告时显示生成按钮，生成后保存并可查阅。历史结果按周期隔离，生成失败不得覆盖已有结果。
- [ ] 验证周期边界、跨月跨年、调度重试、数据缺失、数据库保存读取、中英文切换、报告历史、生成入口、正式站页面访问和媒体显示。
- [ ] 本次不修改线上正式站代码、定时任务、线上报告或 staging 日更；正式部署及启用定时任务留待本地验收后执行。

## 实施任务

1. 核实数据更新标记、现有生成输入与数据库权限；为新报告设计独立持久存储和版本隔离。
2. 实现周期计算、刷新检查、定时生成与失败记录；覆盖调度和时间边界测试。
3. 将现有完整分析生成流程连接到独立存储，保存双语报告及依赖素材；历史缺失时提供受控生成入口。
4. 正式站读取对应周期的持久报告，接通历史、单日选择和媒体，并限制 staging 专属入口。
5. 仅重新生成上周各渠道与 Overview，写入新存储；本地正式站核对实际展示和中英文切换。

## 当前进度（本地准备）

- 已创建独立数据库 schema；旧报告保留，未启用线上定时任务。
- 按最新要求已停止远程生成；已有 Search 结果可在本机正式站预览，新库暂未写入生成结果。
- 本机正式站预览已启动；可访问历史入口和对比控件。
- 日、周、月周期计算和数据更新时间检查已有独立逻辑与测试；尚需将实际各渠道刷新状态、正式生成器和 12:30 UTC 定时任务完整接通并验收。
- 历史报告按环境、周期和对比周期读取新库；缺失时可手动生成并保存双语报告。入口和后台执行链路已完成模拟测试，尚未实际调用远程 AI 验证。
- 页面临时报告仅生成所选位置和语言，按账号及报告条件缓存 24 小时，不写入报告数据库；先核对历史报告，匹配时直接读取。
- 新生成流程使用渠道及 readability prompts，旧 master/manual 入口已停用；线上定时任务待正式部署时切换并验证。
