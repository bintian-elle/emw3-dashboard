# Review workspace

The production application exposes a bottom-left preview toggle and Content Testing Prompts only to the three reviewer accounts in `lib/review-access.ts`. The toggle enters or exits preview directly on the current page. Team notes and screenshot access require active preview. Route handlers check the signed-in identity independently; mutations also require the same origin. The preview cookie is only a preference: every server-side draft feature must use `isReviewPreview()` so that a forged cookie cannot grant access. Existing pages remain the default until a feature explicitly uses that gate. Preview mode blocks advertising refresh and report publication endpoints while allowing isolated Prompt trials and Team notes.

The bottom-right Preview status reads `REVIEW_RELEASE_STATUS_FILE` or `.state/review-release.json`. Set `{"state":"synced"}` once the changes are published. A pending review may set `state` to `pending` and include a bilingual `summary` and the catalog's `changeIds` for links to the updated sections. The status and change links are available only while an authorized reviewer is in preview.

Team notes and screenshot files use `REVIEW_NOTES_DIR` (the old `STAGING_NOTES_DIR` is accepted during migration). Local notes were moved without changing their contents to `.state/review-notes`. Before a future deployment, migrate or mount the existing shared notes directory and verify file counts, checksums, screenshots and deletion permissions; do not delete the original as part of deployment.

Prompt versions and trials use `REVIEW_PROMPTS_DATABASE_URL` and `REVIEW_PROMPTS_RUN_DIR`, with the old names accepted for existing data. The dedicated database/schema and its restricted permissions remain separate from published reports. Local development and `LOCAL_PRODUCTION_PREVIEW=1` save new prompt versions and trial jobs under `.state/review-*`; they do not enqueue remote trials. Existing local trials are retained in `.state/review-prompt-runs-archive`. A local trial worker can be started with `REVIEW_PROMPTS_LOCAL_QUEUE=1` and the existing AI Bluevua connection; it processes only the new local queue. Production requires a separately configured worker for the dedicated Prompt queue before enabling trials online.

`deploy.sh` builds and restarts only the production app. Local changes do not deploy or shut down remote services. Once migration has been verified and explicitly approved for deployment, the old independent staging service and its server-side files can be retired separately after backing up Team notes and Prompt trial media.
