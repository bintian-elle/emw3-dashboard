# Content Testing — 渠道先行、Overview 后置

这是正在测试内容的新编排规则。各渠道正文以本目录对应 Markdown 为准，不继承已经删除的旧总 prompt、checklist、测试目标/假设或旧 JSON 分析章节。已结束测试不在本轮范围。

## 执行顺序与上下文

- 只使用用户指定的同一个 AI Bluevua 原生对话：`Bluevua · Content Testing Insights`。逐个完成 Google Search、PMax、Demand Gen、Meta、Reddit 同期、Reddit lifetime、EDM、Social lifetime，最后生成 Overview。不创建新对话、不派生 agent、不并行生成渠道，也不使用其他对话的旧结论替代本轮结果。Overview 通过本轮文件读取所有已完成结果，不能借用该对话更早的结论。
- 每个渠道遵守自身 prompt 的分析维度和输出章节。章节数量、表格、诊断对象与建议形式可以不同，以内容完整和可读性为先；禁止为统一 UI 删减内容或硬套“建议＋Delta”。
- 本轮直接输出简体中文，无英文生成和翻译步骤。保留真实 Campaign / Creative / Messaging 名称。Video4 等编号后须带实际素材名称；没有名称时使用真实 ID 并说明，不能编名。
- 指标使用输入指定的报告期与冻结快照；Social 和 Reddit lifetime 单独标明，不混入报告期总量。逐渠道核对真实投放窗口、币种、范围和缺失值。零投放、零转化、数据缺失分别解释。

## 数字与渠道间交接

先合计可加总的原始量，再计算比率；不能平均 ROAS/CTR 等。保留平台归因订单的小数。PMax 单素材指标不可相加为方向/Overview，总体沿用提供的 testing asset 口径，缺失 Impressions/CTR 不补成零。Meta/Reddit 从广告出发；EDM 模块点击不冒充整封邮件或购买；Social 的付费/自然来源、帖子龄与 lifetime 限制须保留。

Overview 只能在全部七个渠道本轮结果已完成并校验后生成，同时读取这七份结果、Reddit lifetime 辅助报告与同批权威汇总。不得先写 Overview 再补渠道。它必须综合渠道贡献、效率、素材规模、Messaging 和战略动作；不拼接报告、不掩盖失败渠道，也不重新发明渠道数字。Social 不进入 Dashboard 付费汇总，EDM 不进入 Paid ROAS。没有可比依据不能宣布跨渠道统一赢家。

## 页面交付契约（只统一外壳）

每次返回调用方给定的 JSON schema：报告身份/周期、中文标题、短摘要、按本渠道 prompt 自由组织的 `sections`（每项为标题＋完整 Markdown）、逐 Campaign 的短摘要与针对性详情，以及缺口/来源说明。所有 prompt 要求的章节、对象覆盖、表格、行动与限制必须在正文回应；不要把内部检查编号写进业务正文。

Markdown 用标准标题、段落、列表和 GFM 表格；表格单元格不放原始 HTML，链接必须有真实来源。缺失标为 N/A/未提供，注明关键分母。各 Campaign 详情只写该对象的证据与建议，不复制整个渠道报告。公共版式字段不能反过来限制各渠道内容。

本轮是隔离的中文本地预览：不得写数据库、AI 队列、线上 readout/translation/insight 缓存，不调用刷新/发布接口，不修改项目文件、广告、预算、邮件、账号或发送 Slack。只读分析并在本对话返回结构化结果；控制脚本负责保存到隔离文件，最后复制回本地。已有线上日更和缓存保持不变。

## 结论优先的页面表达（最新要求）

每份报告只写一份 `executive_summary`，这就是页面顶部总结。`sections` 不再包含“核心结论摘要/执行摘要”，直接从各渠道的深度分析、对比或行动部分开始。不要在 summary、sections 或 Campaign 详情中输出报告头、时间戳、冻结/缓存/API/数据采集解释、整段指标定义或范围教学。技术核验与来源保存在结构化审计字段，不展示在业务正文。保留对决策必需的简短限制（例如样本不足，暂不能判断），不用一般性免责声明掩盖结论。已生成的重复摘要由控制脚本/本地适配层移除，无须为这类排版调整重新推理。

引用规则：网页/竞品对比事实需在相关句子旁直接放真实 Markdown 来源链接；本地资料若附有 Google Drive 或 Slack 原始链接，也在对应结论旁引用原链接。不要单列“资料来源”或“数据限制”，不把本地文件路径、任务/缓存编号当作给用户看的来源。没有可核验原链接时不编造链接。

禁止在用户正文报告执行状态，例如“本轮仅完成只读汇总与建议”“没有修改项目文件/广告/预算/数据库/缓存”“未发送 Slack”。这些是内部执行约束，不是测试结论；不得在总结、详情、表格或结尾复述。


**用户正文仅保留业务内容（优先于过程说明）**

正文、摘要和逐 Campaign 短评只能包含：分析结论、必要的数据依据、具体优化建议。不得复述读取了哪些文件/图片/视频、调用或未调用 API、冻结/采集/缓存/数据库/任务状态、字段/schema/内部编号、核验步骤、已完成哪些操作、未修改广告或预算、未发送 Slack 等内部说明。不得另设“资料来源与数据限制”“执行说明”“核验过程”章节，也不得把这些内容改名后塞进表格、脚注或结尾。技术审计仅留在结构化 sources/data_gaps 字段，不进入用户正文。

只在影响决策时保留一句具体限制，例如“仅1笔订单，扩量前需要验证重复性”“模块点击缺失，暂不能判定赢家”。有用的素材观察、数据对比和实际优化建议不得因清理而删除；不要把不确定推断改成确定结论。引用已核实的外部网页或原始 Google Drive/Slack 链接时，直接放在相关句子旁。


**紧凑呈现规则（最新）**

在完整分析的基础上，将可见报告篇幅比此前版本压缩约50%。保留各渠道自己的结构，不统一套模板。优先用紧凑对比表承载数据、用2–3条短要点说明关键差异、用最多4条按优先级排序的动作给出下一步。每个结论只出现一次；表中已有数字不再逐项复述，不为每个指标单设小标题。总结最多2句，先结论后动作；详细洞察只保留最重要的2–3项。每张表尽量不超过6列，每格用一个短句；渠道专用对比表需要更多指标列时允许例外。Campaign短评与详情避免复制完整渠道报告。不能通过删除关键证据、掩盖不确定性或夸大胜者来缩短。Google Search采用其Output Format中的明确字数及表格预算。


## 高管版三板块呈现（最高优先级）

可见报告只有核心结论（executive_summary）、各维度的关键对比、下一步动作。sections仅有后两部分，不按旧版本章节数量生成。各渠道仍保留各自分析重点与表格内容，不套相同指标或建议。用通俗商业语言、短表与短要点，把篇幅压缩约50%；不要长段落、重复结论或后台术语。4.12次转化展示为“约4单”，不足1单不能取整成0；底层计算精度和事实不变。数据缺失/样本少只在影响决策时用一句话交代，不放技术解释。遵守当前渠道Output Format中的字数和表格预算。


## 精简不能省略趋势与流量证据

报告期渠道有可比历史时，关键对比必须保留明确日期的前后期趋势（例如10.13–10.19对10.20–10.26）、曝光/点击原始量及关键细分，并用一句话判断购买的跨日重复或日期集中度。不能用一条“样本不足”代替趋势分析。对比表中的日期是业务证据，不按内部报告头删除。只有lifetime输入的Social等对象不强制编造周比较。Google Search不重复页面已有的花费/收入/ROAS/订单/CPA汇总表，将版面用于曝光点击细分、时间对比和可执行判断。

## Google Search 页面内容分工（新版渠道 Prompt 优先）

本轮更新的 Search 渠道 prompt 决定分析深度、章节和指标，不沿用旧三板块、4000字符或 Campaign 200字限制。核心摘要写入 executive_summary；渠道大盘与全局行动写入 sections；“各 Campaign 与广告组深度下钻”完整写入对应 campaigns[].detail_markdown，不在顶部 sections 再复制一遍。顶部摘要和宏观章节只谈渠道、方向与整体稳定性，不提前诊断单个广告组。每个 Campaign 的所有广告组、必要指标、前后变化、诊断与具体动作仍需保留。

洞察表格与正文自然衔接，不生成工具按钮或交互控件。每张表最多6列，通常不超过8行；指标较多时按流量、购买效率等拆成相邻短表，不减少应覆盖的信息，也不把长段落塞进表格单元格。

## 全渠道本地重生成的页面分工

其他渠道同样遵守最新渠道 prompt 的分析重点与覆盖要求，但页面位置沿用 Search 的分工：渠道摘要与宏观分析留在顶部，Campaign、广告组、单广告、素材或测试模块的深度诊断完整放在对应 campaigns[].detail_markdown 中，不在顶部 sections 重复。EDM 的模块分析放在对应邮件 Campaign；Social 的逐帖与内容格式诊断放在 social-selected-posts 洞察。各渠道仍可使用不同的分析内容与表格，不为了统一版式遗漏对象或指标。

逐渠道完成并保存后，才使用同一轮已完成报告及权威汇总生成 Overview。Overview 只综合渠道、Messaging 和总体测试覆盖，不复制 Campaign 或素材下钻。已确认且 prompt 未变化的 Search 可注明来源后复用；其他旧报告不能冒充本轮重新生成结果。当前只做本地预览，不发布共享数据库或线上缓存。


## 正式日更与发布规则（取代历史本地中文预览说明）

生产控制器先按当前各渠道 Prompt 串行生成英文结果，Campaign 深度内容各归其位；全部渠道完成后才汇总 Overview。中文由独立、低推理强度的纯翻译会话生成，禁止重新分析或更改数字、身份和链接。AI 只返回结果，由控制器保存并发布共享数据库；AI 不自行写库、发布、修改投放或发送消息。

绩效只使用控制器从 Dashboard 提供的本轮数据，不自行调用广告 API 获取其他绩效。项目背景、素材、竞品与内容研究可按已授权方式只读读取本地资料或联网；它们不能替代或改写本轮绩效。

Last Week 每周二生成；若该完整周缺失，则补一次。WTD、MTD 每天生成；Reddit 和 Social lifetime 每天生成一次，并复用于当天其他周期的 Overview。历史中文预览、临时目录与不写共享缓存的说明仅约束 AI 自身，不禁止已获授权的生产控制器发布结果。
