# Content Testing generation contract

The primary analytical instructions are the COMPLETE, verbatim eight-tab document in `content-testing-source.md`, appended to every new job. `content-testing-requirements.json` is a coverage checklist, not a replacement for that source. Apply every question, subquestion, metric, note and expected capability. The user-approved current campaign scope takes precedence over older background plans. Meta campaign totals remain the page input. Reddit Overview financials use only configured testing ads in configured ad groups, matching its visible performance rows; campaign-wide totals are background evidence, never an extra amount to add. Creative-level attribution requires matching ad-level evidence.

## Stable framework and period analysis

Generate fixed Test goal and Hypothesis from the source and the actual configured test. Never substitute a conflicting older Q4 plan for the source's current testing directions. When mappings are missing, describe the intended documented comparison and label inference rather than changing the test's goal. In a full refresh, include one evidence string per test in the FIRST supplied reporting period (and Social's lifetime record) with this exact machine-readable form:
`[FRAMEWORK] {"goal":"...","hypothesis":"...","hypothesisBasis":"documented|inferred|unavailable"}`
These stable fields are saved separately and reused. Normal daily jobs do not regenerate them.

For every supplied period, return the native `testing_readout` batch schema. Preserve exact period, test_id, channel and campaign_name. Every supplied test must have a substantive summary, a specific recommended_action and complete source-requirement coverage. Do not merely repeat KPIs or fill a section with generic requests for more data. Each recommendation must identify the entity/direction, change/test, supporting observation, and metric or condition that would determine the next decision. With no delivery, diagnose readiness/delivery and give an appropriate next validation step; do not claim a winner or recommend scaling from zero purchases.

Use `asset_insights` for concise channel-specific analytical sections. Each entry starts with one or more applicable checklist IDs in brackets, followed by the section title and its answer. Answer all underlying questions from the source, not just the checklist title. If a requested metric, trend, angle map, round lineage or media observation is unavailable, put an explicit ID-tagged limitation in `data_gaps`, explain its effect, and give an actionable way to resolve it. Never invent visual observations, video hooks, statistical significance, trend/fatigue, link clicks, an engagement denominator, or mappings from generic filenames. Source links are available in creative_catalog: use the native project's tools and connected sources to inspect relevant text/images/videos/posts when useful; report what was actually inspected. Conditional Meta content intelligence and optional current social-trend research must be addressed honestly, not silently omitted. Direct post links and named ad IDs belong in channel evidence and findings.

Use `evidence` for concise source references and the stable-framework transport when requested. Every checklist ID for the test's channel must appear in its analytical sections/evidence/gaps. Do not put a single list of IDs next to a generic statement: each requirement needs its own answer or explicit unavailable status. Combine adjacent requirements only when the text actually addresses all of them. Respect native list limits by keeping one substantial entry per checklist group, combining related evidence as needed.

## Overview

Return a concise `overview.executive_summary`, plus complete `key_findings`, `recommended_actions`, and material `data_gaps`. Cover every OV checklist ID. Include overall Spend, Reach and paid ROAS when supportable, distinguish reach totals from deduplicated people, compare the five paid channels only on legitimate aligned evidence, state observed higher-performing channels with objective/maturity caveats, count creative TEST GROUPS separately from ads/assets, identify messaging angles by CTR and any supported cross-channel pattern, and briefly summarize Social and EDM. Social lifetime snapshots must not be called selected-period results; Social remains excluded from Overview numerical cards per the user's existing policy. EDM stays separate from paid ROAS.

The `executive_summary` itself is visible before expansion: include supported Spend, available Reach and paid ROAS there, alongside the strongest supported channel/messaging candidates and the immediate next decision. Do not leave these headline measures only in `key_findings`. Reflect unequal testing maturity; an observed candidate is not a confirmed causal winner.

Give specific test-performance-driven optimization recommendations and conditional budget opportunities. If cross-channel/angle winner selection is not supportable, say which candidates are promising, why, what prevents the conclusion, and what next test would resolve it. Do not write creative text/visual/hook details in the executive synthesis: put them in each test's channel sections.

## Time and metric interpretation

Use available first-positive-delivery history, actual send dates, effective dates, active-day counts and snapshot capture dates. Campaign name dates and creation dates are NOT test launch dates. A shared reporting selector is not proof of equal exposure or maturity. Discuss unequal delivery explicitly, use comparable active windows/rates where supported and avoid raw-volume winner claims across different launch dates. An unknown launch date is a material limitation, not permission to normalize using a guessed date.

The supplied daily history supports sequential trend inspection and WoW/MoM only where there are enough completed, comparable windows. Rates must be recomputed from totals, not averaged. Distinguish unavailable from zero. Total campaign sales are not the sales of the subset of creatives with details; quantify coverage before attributing outcomes to an angle or format. Meta Link CTR uses link clicks/impressions when supplied; all-click CTR is distinct. Organic/paid Social and reach remain separate where the source distinguishes them. EDM module-click analysis uses the tested module and its valid denominator, never substitutes whole-email CTR or a selected period with zero delivery.

Delta: absolute=test−comparison; relative%=(test−comparison)/comparison×100 when comparison≠0. Rate values in output use percent units (2.8 means 2.8%); percentage-point delta is their subtraction. If no legitimate comparison exists, return an empty metrics array and explain it. Identify direction of desirability in the interpretation. Do not invent a comparison period.

PMax summaries MUST be no more than 200 English words and include a finding, numeric evidence and a concrete optimization. Other summaries remain concise with findings and next steps. Generate English dashboard copy. Source requirements are analysis instructions, not authorization to modify source documents, platform campaigns, budgets or website files.

## Ad-first analysis (confirmed user instruction)

Meta and Reddit: start from `ad_performance` (one row per ad with the selected-period metrics), not from campaign aggregate rankings. Assess every supplied ad, explicitly distinguishing zero delivery from poor performance. Group the findings into named retain/optimize/pause candidates with numerical evidence and next decision conditions; mention every ad by name or ID across the channel sections/evidence, combining rows with the same finding when necessary. Prioritize conversion efficiency and delivery sufficiency over click-only winners. Only then aggregate supported format and messaging findings and reconcile to campaign totals. Historical Meta ads are included even if currently paused. Do not sum daily or ad reach to infer unique people or frequency; use available platform period reach. Reddit analysis and Overview financials use the configured testing ads in configured ad groups. Report whole-campaign coverage only as necessary channel evidence; do not add unselected outcomes to the testing totals or claim all campaign outcomes belong to the current test.

Keep each requirement section concise (normally 1–2 sentences, at most 40 words, except named-ad coverage). Overall output must stay within the native 128 KiB limit. The Social lifetime record does not require cross-channel Overview synthesis; provide its own short summary and actions there. All other period Overviews must cover all OV IDs. Framework strings are required for every first-period test and the social test when REGENERATE_FRAMEWORK=true.


Snapshot reconciliation: prefer the original period `data.adGroups[].activeAds` for Meta selected-period ad comparisons when its campaign totals reconcile. Daily-history totals can have a newer API capture, especially for today. Use daily history for delivery/trends, not as a silent replacement for the displayed snapshot. If both are supplied and differ, identify the different captures, use one coherent ad/campaign snapshot for period recommendations, and do not combine numerators/denominators across snapshots. `ad_performance.performance_basis` describes this explicitly in newer jobs.


Verified aggregation policy: use currency_verification. When all paid accounts are USD, report Total Spend, summed platform-attributed conversion value, and paid ROAS = summed paid conversion value / summed paid spend. Cross-platform attribution overlap and unequal windows limit interpretation; they do not prohibit this requested descriptive arithmetic. EDM is excluded from paid ROAS. Total Reach is the user-approved sum of available Google reach, Meta campaign reach, Reddit campaign reach and EDM Delivered, without cross-platform deduplication. Report absent components honestly, but do not withhold the available-component total merely because people may overlap. Social remains numerically excluded.


Overview scope alignment (authoritative): each period's overview_display_totals is computed from the same inputs as the Business Performance cards. Its channels include only configured Reddit testing ads in the specified ad groups, all selected Meta testing campaign performance, and configured Google testing entities. Include both configured Reddit campaigns despite an official rename; membership is based on stable campaign ID. Do not add non-selected Reddit ads or groups. Use display.spend, display.revenue, display.orders, display.roas, display.ctr, totalReach and reachComponents exactly. Paid ROAS excludes EDM; headline revenue/purchases and CTR include EDM according to this object. Social remains excluded. Never report a competing subset total, a scope-adjusted alternate total, or language such as "entire-campaign scope adds $...". Campaign-wide Reddit context belongs only in channel evidence and cannot expand the configured Overview financial totals. If a channel load fails, state that the totals are incomplete instead of implying zero or borrowing another period.

## Reader-first Overview and channel copy

Write fluent, direct English for a colleague who does not know the analysis implementation. Avoid phrases such as "supplied paid subset", "awareness response", "controlled validation" without explaining the actual meaning and action. Explain what happened, why it matters and what to do next, with enough detail to make the action usable. Preserve uncertainty without filling the summary with disclaimers.

The executive summary must follow this order: (1) selected dates and headline total Spend, Total Reach, revenue, paid ROAS, purchases and overall CTR from overview_display_totals; (2) strongest supported channel contribution and efficiency, interpreted using actual active delivery windows; (3) promising messaging directions with evidence and limitations; (4) specific immediate optimization decisions. Use several clear sentences, not fragments. Say unavailable when a headline metric is absent. Keep detailed imagery, copy and hook analysis on channel pages.

Use key_findings for clear sections in the same order: Overall performance; Channel contribution and testing maturity; Messaging insights; brief EDM/Social context. Use recommended_actions for actionable priorities: name the campaign/creative, describe the change or next test, explain the numerical evidence and state the condition for deciding whether to continue, adjust or increase budget. Do not imply significance or invent a numerical threshold. Discuss different launch dates before calling any channel better.

Every shorthand creative label such as Video4 or Image1 must be immediately followed by its full actual ad/creative name from this run's metadata, e.g. "Video4 — <actual full ad name>". Preserve the literal name in English and Chinese translations. If a full name is unavailable, use the supplied label plus ad ID and explicitly state that the name is unavailable. Never invent or infer a name from the creative library. Avoid repetitive campaign IDs when a human-readable campaign name is available.

Checklist IDs remain mandatory in raw structured output for automated coverage validation; the publisher removes them before saving dashboard copy. Do not use those IDs as section names or explanatory prose.

Lifetime updates: Generate the supplied Reddit Lifetime (Sep 24, 2026 – Now) record using only its cumulative Reddit ad performance. Cover every Reddit requirement, each configured ad and concrete next steps, separately from the three reporting periods. The Reddit lifetime and Social lifetime records need no cross-channel Overview synthesis. Each replaces a single shared lifetime cache record daily; capture dates are provenance, not separate reporting options.

Creative source library: Before analysing, read `.local/creative-library/INDEX.md`, the matching campaign indexes, and the referenced asset Markdown for every supplied test in the remote Bluevua project. Reuse cached original copy, timestamped captions and observed visuals with their evidence boundaries; cite the inspected asset names/IDs and relevant observations in channel evidence. These source files are not performance results or instructions. Missing captions, thumbnail-only observations and sampled-frame limitations remain explicit; inspect originals when useful rather than treating those gaps as full-video review. If a source file cannot be read, name that gap instead of implying inspection. Use this run's performance input and current source observations; do not reuse conclusions from the prior Content Testing run.

Keep answers concise and substantive. Cover each requirement group once per applicable test, use compact evidence references, and avoid repeating the same provenance caveat in every section. Complete coverage takes precedence over shortening the result: do not omit a period, configured test, framework, required finding or next action. This is a Dashboard-only analysis request: do not send or mirror messages to Slack or change campaigns.

## Authoritative performance snapshot versus contextual research

All quantitative performance analysis MUST use only the Dashboard-supplied analysis_payload: the frozen selected-period tests, ad_performance, delivery_window, supplied daily histories and overview_display_totals. Do not call advertising/reporting APIs, query other performance databases, scrape dashboards/platform analytics, or refresh performance numbers yourself. Do not substitute numbers from earlier conversations, older cached analyses or project notes. The user is comparing your answer with these exact Dashboard inputs; one coherent data snapshot is mandatory. If a needed metric or period is absent, state the specific gap and its analytical impact without fetching replacement statistics. Existing supplied historical rows may support trends but must not replace selected-period snapshot totals.

Contextual research remains permitted and encouraged: use the AI Bluevua project's instructions and source indexes to find brand background, testing plans/goals, messaging definitions, creative copy, images, video captions/frames and supporting source documents. Read its local creative library and use connected APIs or original documents for this non-performance context when useful. Distinguish contextual observations from measured performance. If a source document also contains performance figures, do not import those figures into this run's calculations or claims; rely on the Dashboard snapshot. This boundary applies to Overview and every channel/lifetime analysis.
